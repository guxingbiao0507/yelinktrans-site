# 域名与Microsoft 365邮箱DNS保护说明

## 重要结论

`yelinktrans.com` 同时用于官网和Microsoft 365企业邮箱。网站上线时可以修改网站解析记录，但不能因为部署网站而删除、覆盖或遗漏邮箱记录。

## 变更前必须完成

1. 登录当前DNS服务商控制台；
2. 导出整个 `yelinktrans.com` DNS区域，或逐页截图并另存所有记录；
3. 记录当前域名服务器（NS）；
4. 在Microsoft 365管理中心打开域名设置，核对微软要求的记录；
5. 确认James和Mike邮箱当前收发正常；
6. 约定DNS变更时间和回滚负责人。

## 必须保护的邮箱记录类型

以下只列记录类型，不填写具体值。部署人员必须以当前DNS控制台和Microsoft 365管理中心显示的实际值为准，不能根据示例猜测。

- MX：决定邮件投递位置；
- SPF TXT：声明允许代发邮件的服务器；
- DKIM CNAME：通常包含两个选择器；
- DMARC TXT：通常位于 `_dmarc.yelinktrans.com`；
- Autodiscover CNAME：供Outlook自动发现邮箱配置；
- Microsoft域名验证TXT或其他仍在使用的验证记录。

## 推荐变更方式

优先保留现有DNS服务商，只新增网站托管平台要求的记录：

- 根域名 `@`：按托管平台要求配置A、ALIAS或ANAME；
- `www`：通常配置CNAME，并在托管平台设置301跳转到根域名；
- 不触碰邮件相关的MX、TXT和CNAME记录。

只有当托管平台强制要求迁移域名服务器时，才考虑修改NS。迁移NS前，必须先在新DNS平台完整重建并核验全部记录，再切换NS。

## 上线后的邮箱验收

至少完成以下测试：

1. 外部个人邮箱向James和Mike各发送一封邮件；
2. James和Mike分别回复外部邮箱；
3. James与Mike互发邮件；
4. 检查邮件是否进入垃圾邮件；
5. 使用Outlook桌面版和网页版各测试一次；
6. 重新核对MX、SPF、DKIM和DMARC是否仍然可查询。

## 回滚触发条件

出现以下任一情况，应暂停网站上线并优先恢复邮箱：

- 外部邮件无法投递；
- Outlook持续提示重新配置账户；
- MX记录指向错误；
- SPF、DKIM或DMARC记录在迁移后缺失；
- 网站托管平台要求删除与邮箱相关的记录。

不要为了让网站尽快上线而接受邮箱中断。企业邮箱属于比官网更关键的生产服务。
